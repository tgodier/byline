# Contributing to Byline

Thanks for your interest in contributing to the Byline specification.

## Ways to Contribute

### Report Issues

Found a problem with the spec? Have a suggestion? [Open an issue](https://github.com/tgodier/byline/issues) on GitHub.

Good issues include:

- Ambiguities in the specification
- Missing elements that would be useful
- Unclear wording or examples
- Compatibility concerns with existing standards
- Implementation challenges

### Propose Changes

For substantive changes to the specification:

1. Open an issue first to discuss the change
2. Explain the problem you're solving
3. Describe your proposed solution
4. Consider backwards compatibility

Changes are discussed in issues before being incorporated. This keeps the spec stable and ensures broad input.

### Share Implementations

Built something with Byline? Let us know by [opening an issue](https://github.com/tgodier/byline/issues) with:

- Project name and link
- Brief description
- What parts of Byline you support

We'll add it to the implementations list on the website.

### Improve Examples

The `examples/` folder contains sample feeds. PRs welcome for:

- Additional feed examples
- Corrections to existing examples
- Examples in different scenarios

### Fix Typos

Small fixes like typos can go directly in a PR without prior discussion.

## Style Guidelines

When writing specification text:

- Be precise and unambiguous
- Use active voice
- Keep sentences short
- Provide examples for complex concepts
- Follow RFC 2119 conventions for requirement levels (MUST, SHOULD, MAY)

## Code of Conduct

Be respectful and constructive. We're all here to make feeds better.

## Questions?

Not sure if something is worth an issue? Open one anyway. We'd rather have the discussion than miss good feedback.
